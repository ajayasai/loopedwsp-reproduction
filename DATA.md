# Data and provenance

## Official Maze-Hard grids

The headline 30×30 evaluation uses Sapient AI’s `sapientinc/maze-30x30-hard-1k` dataset, released with the Hierarchical Reasoning Model study. Each split contains 1,000 labeled mazes. This reproduction uses the official training split for development and the official test split for held-out scoring. [Dataset](https://huggingface.co/datasets/sapientinc/maze-30x30-hard-1k) · [HRM study](https://arxiv.org/abs/2506.21734)

Run this command from the project root to retrieve both splits. It uses the Python standard library.

```sh
python scripts/fetch_maze.py
```

The downloader fetches directly from Hugging Face at revision `549754de3d67eebe57b6b22c7d226b9412d55b07`. It checks the complete file against the digest recorded in the corresponding evaluation report. [Pinned file listing](https://huggingface.co/datasets/sapientinc/maze-30x30-hard-1k/tree/549754de3d67eebe57b6b22c7d226b9412d55b07)

| Local destination | SHA-256 of the published CSV | Evaluation record |
|---|---|---|
| `data/maze/train.csv` | `25f9e39b5aee16967da41ba63b2d1d75cf608c2360d8a1419d827f9859dbafa0` | [Development](results/maze/dev.json) |
| `data/maze/test.csv` | `5120d52088fb3f8036e62e90103808a79ba58847d8601f9451f40991b0903a62` | [Held-out test](results/maze/test.json) |

Use `--split train` or `--split test` to fetch one split. Set `--output-dir PATH` for another destination. Existing files are verified in place. A checksum mismatch stops the command and preserves the existing file.

The pinned dataset repository contains the CSVs, an attributes file and an editor lock file. It provides no dataset card or explicit redistribution license. This release supplies the direct download path and checksums. Sapient’s HRM code repository has an Apache-2.0 license and retrieves the CSVs from Hugging Face in its dataset builder. [Pinned dataset metadata](https://huggingface.co/api/datasets/sapientinc/maze-30x30-hard-1k/revision/549754de3d67eebe57b6b22c7d226b9412d55b07) · [HRM dataset builder](https://github.com/sapientinc/HRM/blob/ac15626f8db096a63c775b84c9dc868776a6feda/dataset/build_maze_dataset.py#L21-L35) · [HRM code license](https://github.com/sapientinc/HRM/blob/ac15626f8db096a63c775b84c9dc868776a6feda/LICENSE)

## Generated cases and results

- **Larger mazes.** The scale evaluation draws 50 fresh 60×60 mazes and 40 fresh 100×100 mazes from fixed seeds using the generation procedure in the LoopedWSP demo. A separate breadth-first search supplies the shortest-path labels. The corpus lock records input and target hashes. [Generator and grader](scale/corpus.py) · [Corpus lock](scale/corpus-lock.json) · [Upstream generator](https://github.com/mbzuai-oryx/LoopedWSP/blob/2752cd9f2d2e1e3e30e6686b3dbc23d8bcab875c/weights/run.py#L295-L312)
- **Graph search, parity and reasoning chains.** The length sweep uses newly generated examples and fixed random seeds, with separate development and held-out streams. [Evaluation harness](lengths/experiment.py) · [Corpus hashes](lengths/corpus-lock.json)
- **Hanoi and Checker Jumping.** Each size specifies a deterministic starting position. The evaluation saves emitted moves and replays them against the puzzle rules. [Independent verifier](puzzles/verify.py) · [Puzzle rules](https://arxiv.org/html/2506.06941v1#A1.SS1)
- **Practical applications.** Inventory, scheduling and telemetry cases are synthetic streams generated by this project. The frozen input and label checksums identify the corpus used in the GPU evaluation. [Generator harness](applications/experiment.py) · [Corpus lock](applications/corpus-lock.json)
- **Pointer chasing and directed reachability.** The project generated 48 development and 1,280 test queries per task on 64 randomly relabeled vertices. Every adjacent pair in an array is a counterfactual pair. The generator writes the inputs and labels and records each array's shape, dtype and SHA-256. [Generator](graph_depth/corpus.py) · [Cases](graph_depth/cases.npz) · [Manifest](graph_depth/cases-manifest.json)
- **Creative applications.** Each task has 16 development and 256 held-out records. Color grids, monospaced paragraphs and film rankings are synthetic, and the same encoded input cannot appear in two records for a task. The compressed JSON includes the raw inputs and oracle answers used for evaluation. [Inputs and targets](creative/cases.json.gz) · [Corpus and tensor hashes](creative/freeze.json) · [Generation and evaluation](creative/experiment.py)

- **Workshop applications.** The project generated mobile designs, stacks of colored rectangles and parity-protected musical events, with 16 development and 256 held-out records per task. Roll inputs contain only observed holes and include clean frames, single flips and double flips. Sizes count ornaments, layers or beats. The PNG and WAV in the results are exports of held-out model predictions. [Protocol](workshop/protocol.json) · [Inputs and gold answers](workshop/cases.json.gz) · [Per-cohort hashes](workshop/freeze.json)

- **Hydrology, astronomy and sports.** The project generated integer terrain maps, synthetic telescope light curves and legal bowling scorecard prefixes. Each task has 16 development and 256 test records. The telescope generator stores injection metadata separately from the observation record passed to the model and the reference detector. Sizes represent grid side length, number of cadences or number of started frames. [Frozen data](fieldlab/cases.json.gz) · [Study design](fieldlab/protocol.json) · [Runnable inputs](fieldlab/examples)

- **Turkish morphology, crystallography and auctions.** The project generated regular synthetic noun stems with number and case requests, quarter-cell point motifs with lists of reflections, and bids on bundles of four goods. Each task has 16 development records and 256 held-out records. Eight additional worked checks cover real Turkish word forms, four known motifs, and three hand-calculated auctions. All inputs, reference answers and weights were frozen before the GPU test. [Cases](crossfield/cases.json.gz) · [Worked checks](crossfield/checks.json) · [Generation protocol](crossfield/protocol.json) · [Frozen hashes](crossfield/freeze.json)

- **Tree rings, weaving and braids.** This project generated the ring-width series, rising-shed drafts and signed three-strand braid words from seeded streams. The ring series include transformed excerpts, missing widths, repeated patterns and independently drawn samples. The loom data include straight, point and random threadings. The braid words include random crossings and words with inserted inverse pairs. Each task has 16 development and 256 held-out records. Thirteen worked cases are stored separately. [Frozen cases](atlas/cases.json.gz) · [Worked cases](atlas/checks.json) · [Protocol and seed](atlas/protocol.json)

- **Contour maps, ancestral plumage and Clifford circuits.** This project generated scalar grids, synthetic three-state plumage on supplied binary trees, and three-qubit circuits with Pauli queries. The 256 held-out records per task include 250 distinct grids after subtracting the contour level, 256 distinct labeled tree inputs and 250 distinct gate lists. One held-out circuit record uses a development gate list with different queries. All full records are disjoint across development and test. The circuit generator uses the reference to select four deterministic and four unbiased observables per test record. It passes only the gates and the shuffled observable words to the model. [Frozen inputs and answers](frontier/cases.json.gz) · [Thirteen worked checks](frontier/checks.json) · [Protocol and seed](frontier/protocol.json)

The files under `results/` report this reproduction’s measured scores, timings and verification outputs. The upstream study and its reference weights are available from the authors.
